# 컴파일 시스템의 동작 방식에 대한 이해가 중요한 이유

## 프로그램 성능 최적화

프로그램 성능 최적화를 위해서는 C 컴파일러가 C 프로그램을 기계어로 번역하는 방식에 대한 이해가 필요하다.

---

- `switch`문이 연속된 `if-else`문 보다 더 효율적인가?
- 함수 호출에는 어느 정도의 오버헤드가 발생하는가?
- `while` 루프가 `for` 루프보다 효율적인가?
- 포인터 참조가 배열 인덱스보다 더 효율적인가?
- 참도로 전달된 인자 대신 지역 변수에 합계를 누적할 때 왜 루프가 더 빨리 실행되는가?
- 산술 표현식에서 괄호 위치에 따라 함수의 실행 시간이 어떻게 바뀌는가?

---

Chapter3에서 컴파일러가 C 구조를 어떻게 번역하는지 설명한다. \
Chapter5에서 C 프로그램의 성능을 튜닝하는 방법에 대해 설명한다. \
chapter6에서 메모리 시스템의 계층적 특성, C 컴파일러가 데이터 배열을 메모리에 저장하는 방식 등을 통해 C 프로그램이 더 효율적으로 실행 되는 방법에 대해 설명한다.

## link-time error에 대한 이해

---

- 링커가 참조를 해결할 수 없다는 것은 어떤 의미인가?
- 정적 변수(static variable)와 전역 변수(global variable)의 차이는 무엇인가?
- 서로다른 C파일에 같은 이름의 전역 변수를 정의하면 어떤 일이 발생되는가?
- 정적 라이브러리와 동적 라이브러리의 차이는 무엇인가?
- 명령줄에 라이브러리를 나열하는 순서가 왜 중요한가?
- 왜 일부 링커 관련 오류는 실행 시점(run time)이 되어서야 나타나는가?

---

## 보안 취약점 회피

안전한 프로그래밍을 배우기 위해서는 데이터와 제어 정보가 프로그램 스택에 저장되는 방식의 결과를 이해해야한다.
어셈블리어 학습의 일환으로 Chapter3에서 스택 규칙과 버퍼 오버플로우 취약점을 설명한다.
또한 공격의 위협을 줄이기 위해 프로그래머, 컴파일러, 운영체제가 사용할 수 있는 방법도 설명한다.
